# Metaverse MVP — 설계 문서

> "뛰어다니지 않는 메타버스"
> 로블록스를 넘어선 새로운 가상 공간 패러다임

---

## 1. 핵심 문제 인식

### 기존 메타버스의 구조적 문제
| 플랫폼 | 이동 방식 | 낭비되는 시간 |
|--------|-----------|---------------|
| Roblox | 걷기/달리기/점프 | 맵 이동 시간 전체 |
| Decentraland | 걷기 | 높음 (거대한 빈 땅) |
| VRChat | 걷기/순간이동 혼재 | 중간 |

**인사이트**: 가상 공간에서 "이동 자체"는 목적이 아니다.
목적은 **만남**, **경험**, **창작**이다.

### 로블록스 블록 미학의 실제 이유
- 렌더링 최적화: 평면(평면 법선벡터) → 곡면보다 GPU 연산 1/10
- 물리 충돌 계산 단순화: AABB(axis-aligned bounding box)
- UGC 진입장벽 최소화: 누구나 블록을 쌓을 수 있음

→ 그러나 이 제약들은 **2010년대 기준**이다.
현재 브라우저/모바일 GPU는 훨씬 강력하다.

## 2. 새로운 비전: "공간 갤러리" 모델

### 컨셉
```
[홈 화면 — 갤러리 뷰]
    │
    ├─ 친구 공간들이 카드/썸네일로 보임
    ├─ 클릭 → 즉시 입장 (로딩 없음, WebSocket 연결)
    └─ 공간 안에서도 "포털 창문"으로 옆 방이 보임
```

물리적 이동 없음. **공간들 사이의 관계**가 UI로 표현된다.

### 이동 패러다임 변경
```
기존: [나] → 걷기 → [목적지]  (시간 소모)
새로: [나] + [목적지 선택] → 즉시 컨텍스트 전환
```

영감:
- **Figma의 멀티플레이어 커서**: 공간을 이동하지 않고 같은 화면에 존재
- **Notion의 중첩 페이지**: 계층적 공간 이동
- **Discord Stage**: 공간 개념이 있지만 물리 이동 없음

## 3. 시각적 미학 — 블록 없이 가볍게

### 옵션 A: 로우폴리 + 부드러운 셰이딩 (추천)
```
특징:
- 폴리곤 수는 적지만 Normal Map으로 부드러움 표현
- Flat Shading → Gouraud Shading으로 전환만 해도 크게 달라짐
- 예시: Monument Valley, Alto's Odyssey
렌더링 비용: 블록 대비 +20~30% (무시 가능한 수준)
```

### 옵션 B: 2.5D 아이소메트릭
```
특징:
- 하비보 호텔 + 스타듀밸리 스타일
- 3D처럼 보이지만 실제론 2D 연산
- 캐릭터는 스프라이트 (8방향 애니메이션)
렌더링 비용: 가장 저렴
UGC 제작: 도트 그래픽 에디터로 가능
```

### 옵션 C: SDF (Signed Distance Field) 기반 유기체형
```
특징:
- 블록과 정반대 — 물처럼 흐르는 형태
- Metaball처럼 오브젝트들이 부드럽게 합쳐짐
- Three.js + GLSL shader로 구현 가능
렌더링 비용: 높음 (GPU-bound)
UGC 제작: 어려움 (파라미터 기반)
```

### 옵션 D: 벡터/SVG 기반 평면 공간
```
특징:
- 완전히 2D, 하지만 레이어로 깊이감 표현
- CSS 애니메이션으로도 구동 가능
- 캐릭터 = SVG 아바타 (NFT처럼 조합 가능)
렌더링 비용: 가장 저렴 + 확장성 최고
```

**MVP 권장**: **옵션 D (2D SVG) 또는 옵션 B (2.5D 아이소메트릭)**
→ 브라우저 기반으로 즉시 실행 가능, 설치 불필요

## 4. MVP 핵심 기능 (최소 범위)

### Phase 1 — "방" 개념
```
[ ] 유저가 자신의 "방"을 가짐
[ ] 방에 오브젝트 배치 (드래그 앤 드롭)
[ ] 다른 유저 방 방문 (URL로 즉시 접속)
[ ] 방문자 목록 실시간 표시
[ ] 기본 채팅
```

### Phase 2 — "공간" 개념
```
[ ] 방들이 연결된 "동네" 구성
[ ] 갤러리 뷰: 내 피드에 친구 방들이 표시
[ ] 공간 내 미니게임 embed (iframe 또는 WebGL)
[ ] 아바타 커스터마이징 (옵션 D 기준: SVG 레이어 조합)
```

### Phase 3 — "경험" 개념
```
[ ] 유저가 직접 미니 공간 제작 (노코드 에디터)
[ ] 공간 공유/발견 피드
[ ] 수익화 (공간 입장료, 아이템 판매)
```

## 5. 기술 스택 (Unity vs Web)

### Unity 선택 시
```
장점: 3D 완성도, 물리엔진, 에셋스토어
단점: 설치 필요, 로딩 시간, 모바일 용량 큼
적합한 경우: 몰입형 3D 경험이 핵심일 때
```

### Web (Three.js / React Three Fiber) 선택 시
```
장점: URL 공유로 즉시 접속, 설치 없음, SEO 가능
단점: 복잡한 3D는 한계
적합한 경우: 소셜/공유 메타버스 MVP
```

### 권장: Web-first MVP
```
Next.js (현재 스택)
  + React Three Fiber (Three.js React 래퍼)
  + Rapier (경량 물리엔진, Rust/WASM)
  + Liveblocks or Partykit (실시간 멀티플레이어)
  + 아바타: Ready Player Me API (무료 아바타 생성)
```

## 6. "이동 없는 이동" UX 설계

### 공간 전환 방식
```
1. 포털 방식: 화면 가장자리에 다른 공간이 보임
   → 클릭하면 카메라가 부드럽게 pan해서 이동
   (실제로 걷는 게 아님 — 카메라 이동)

2. 맵 방식: 상단에 미니맵 항상 표시
   → 클릭 포인트로 즉시 이동 (워프)

3. 카드 방식: ESC 누르면 갤러리 뷰
   → 공간들이 카드로 표시, 클릭하면 zoom-in 전환
```

### 소셜 인터랙션 (이동 없이)
```
- 아바타가 "공간" 안에 있으면 그냥 같이 있는 것
- 대화: 클릭 → 말풍선 또는 음성
- 리액션: 이모지 플로팅
- 위치 개념 최소화: "A방에 5명 있음" 정도로만 표시
```

## 7. 차별화 포인트

| 요소 | Roblox | 우리 MVP |
|------|--------|----------|
| 이동 | 달리기/점프 | 즉시 워프/클릭 |
| 미학 | 블록형 | 유기적/벡터 |
| 접근 | 설치 필요 | URL 즉시 접속 |
| 공간 단위 | 거대한 월드 | 작은 "방" 연결 |
| 목적 | 게임 | 소셜 + 경험 |

## 8. 다음 단계 (MVP 빌드 순서)

1. **프로토타입**: 단일 "방" — 아바타 표시 + 실시간 동기화
2. **아바타 에디터**: SVG 조합 또는 Ready Player Me 연동
3. **방 꾸미기**: 드래그 앤 드롭 오브젝트 배치
4. **소셜**: 친구 목록, 방 방문, 채팅
5. **발견**: 피드, 추천 공간
